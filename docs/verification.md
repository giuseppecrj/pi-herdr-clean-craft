# Verification

There are two commands. Run the default suite from the package root:

```sh
npm test
```

It uses only Node's built-in test runner and needs no installed dependencies. The Pi CLI must be on `PATH`, or named by `CLEAN_CRAFT_PI_BIN`. Without it the discovery and delivery tests fail with a `BLOCKED` message. They are required checks and never pass by skipping. The harness lifecycle checks start short-lived Node processes and loopback servers and read Linux `/proc`. On another platform they also fail with `BLOCKED`. The default suite does not need Herdr, pi-herdr-agents, or pi-herdr-pstack, and it never starts them.

The host integration gate is a separate, explicitly required command. `npm test` does not run it:

```sh
CLEAN_CRAFT_HOST_ROOT=/absolute/path/to/pi-herdr-agents \
CLEAN_CRAFT_PSTACK_ROOT=/absolute/path/to/pi-herdr-pstack \
npm run test:integration
```

A `BLOCKED` result exits nonzero because a gate that could not run has not passed. Treating it as a skip would let a missing prerequisite look like a green release check.

## Sibling links

A skill may link another shipped skill only at `../<name>/SKILL.md`, relative to the skills directory that holds both. That records a sibling dependency, not a file the linking skill owns. The checker does not follow the sibling's own links, because the sibling is checked on its own. Owned references remain the only input to the package allowlist. The checker rejects a link to a missing sibling, to any other file or directory inside a sibling, to anything outside the skills directory, and to a sibling whose real path, after symlinks, lies outside it. The same check runs against the source tree and the extracted tarball.

## Retry fixture

`test/fixtures/retry-eligibility` is test-only and never packed. It holds one small retry-eligibility program: a domain function that decides retry or stop from a transient or permanent failure and the attempt count, an adapter that maps error codes and calls it, a constant-only infrastructure module, and literal behavior cases. The cases include NaN attempt counts and maximums, which the domain's `number` type admits, so a refactor must preserve the base comparison's handling of them. `base/` is the correct program. Each directory under `variants/` replaces whole source files with a complete alternative: a behavior defect, a renamed export that fails to load, a structurally different correct implementation, and a domain module that imports infrastructure. `mutants/boundary` replaces one file and differs from the base by exactly one line. The main behavior, refactor, dependency, and boundary-mutant states are checked-in whole-file snapshots. Negative controls derive malformed or throwing mutants in test-owned copies. The loader rejects any mutant that changes zero or several lines, changes the line count, replaces several files, or targets a file outside the base `src/` tree.

Each test writes its state into its own temporary directory. A worker process, started with the test-owned environment, preloads every source module under Node's synchronous module hooks. It then reports the hash of each loaded source file, the import edges it resolved, and any module that failed to evaluate, and waits. On receipt of that record, the parent tells it to run the fixture tests through `node:test` in the same process, tells it to fail, or kills it. The hash is taken from the bytes before evaluation, so a matching hash alone shows only that the mutated file was read. After worker closure, the test accepts the checkpoint as evidence that a state loaded only when the expected hash is present and no module failed to evaluate. A negative control interrupts a mutant whose first line throws and shows that the evidence gate refuses the checkpoint despite a matching hash. The worker never writes to the workspace, and the parent writes all files. Red and killed results require a named test that failed with a Node `AssertionError`. A load failure, a worker error, and a nonzero exit status are recorded as such and never count as red or killed.

The mutation trial checks for a green baseline and confirms the target still matches the base before writing the mutant. After the worker closes, the parent restores the file from the in-memory snapshot, compares the whole workspace with the snapshot byte for byte, and runs the unmutated tests again. A workspace that does not match is kept and its path reported instead of being deleted. Negative controls cover a red baseline, a drifted target, a stray file, and malformed mutants. Worker deadlines are explicit, but no test exercises a timeout, and nothing here recovers from the death of the test process itself.

The import edges come from runtime resolution. Type-only imports, which Node erases, and imports on paths that never execute do not appear, so the fixture's boundary check does not measure them. The fixture TypeScript runs through Node's built-in type stripping, which does not type-check. Type checking during development used an editor language server, which no test runs.

## Frontmatter grammar

The skill checker reads a deliberately small subset of YAML: one `key: value` pair per line, with each value either plain or double-quoted without escapes. Spaces and tabs around a value are ignored, while spaces inside double quotes are kept. Plain values resolve the way Pi's YAML 1.2 core-schema parser reads them, so `null`, `~`, an empty or whitespace-only value, `true`, `False`, `123`, `0x1F`, and `.inf` are not strings. Names and descriptions must be strings, so quote any that would otherwise read as another type. `disable-model-invocation` must be an unquoted boolean. Pi treats only the boolean `true` as explicit-only, and a quoted `"true"` is a string.

## Isolation

Each Pi or npm process runs with a test-owned temporary home, agent directory, XDG directories, working directory, npm cache, and empty npm configuration. The environment is built from an allowlist that carries no credentials. Pi runs offline with telemetry and version checks disabled, no extensions, context files, tools, prompt templates, or themes, no session file, and no project trust. The only package source in its settings is the path under test. Every process has an explicit timeout, and the temporary directories are removed afterwards.

npm reads project configuration from the package root's `.npmrc`, and empty user and global configuration do not prevent that. Therefore npm never runs in the checkout. The tests pack a staged copy inside a test-owned directory. The copy is faithful except for three exclusions. It omits `.npmrc` and `.git` at any depth, because npm never packs either. It also omits the root `node_modules`, because npm packs it only for bundled dependencies, which the manifest check forbids. Plans, tests, fixtures, `.audit`, and nested `node_modules` stay in the copy, so an allowlist that wrongly includes them still fails the exact inventory check. If the temporary directory sits inside the checkout, staging skips it rather than copying it into itself. A regression packs a test-owned candidate whose `.npmrc` redirects npm's logs to a sibling directory. It checks that the redirect target is never created, that npm's log lands in the test-owned cache, and that the extracted tarball holds exactly the allowlisted files with unchanged contents.

This registers the package only in temporary settings. It does not install anything into your own Pi configuration.

The delivery checks add a loopback model endpoint on `127.0.0.1` with a dummy key in test-owned `models.json`. Each request is tied to the run by a random path segment in that endpoint's URL. Retries, compaction, cache warming, analytics, and install telemetry are off. Pi runs without tools, so the scripted reply cannot run anything. Once the endpoint starts, it and Pi are closed even if setup fails, and any observation the endpoint or the RPC log lost fails the check.

## Host integration gate

The gate tests the packed candidate, not the checkout. It packs this package with the same staging helper as the package checks, extracts the tarball, and refuses to continue unless the tarball holds exactly the inventory.

### Inputs

`CLEAN_CRAFT_HOST_ROOT` and `CLEAN_CRAFT_PSTACK_ROOT` must name existing local package directories by absolute path. The host must be `pi-herdr-agents` at exactly the version in this manifest's `peerDependencies`. pstack must be `pi-herdr-pstack`, and its version is recorded but not pinned. Both must declare extension entry points that exist. `CLEAN_CRAFT_PI_BIN` and `CLEAN_CRAFT_HERDR_BIN` override a `PATH` lookup for `pi` and `herdr` and must be absolute executable paths. The gate never searches your Pi configuration or guesses install locations. It records the versions it ran, plus a content digest of each package. `CLEAN_CRAFT_EVIDENCE_DIR`, when set, receives a new `run-<time>-<random>` directory for every run, and earlier runs are never overwritten. When it is unset, a run that fails, or whose teardown is not clean, writes its evidence to a new `clean-craft-evidence-<random>` directory in the system temporary directory, and the test prints that path. Only a passing run with a clean teardown and no requested destination keeps no evidence. Evidence holds the report, the request ledger, the RPC and Herdr logs, and the host's launch scripts. It never includes the run directory or upstream module caches. The gate needs Linux, because it identifies processes and sockets through `/proc`. Other platforms report `BLOCKED`.

### Isolation and lifetime

Each run creates a fresh short directory under `/tmp`, whatever `TMPDIR` says. The directory holds:

- home and XDG directories;
- a Pi agent directory with test-owned `settings.json`, `models.json`, and task-model configuration;
- a session directory and a working directory;
- a `bin` directory of symlinks to the selected `pi`, `herdr`, and `node`.

One environment is built from an allowlist, with no proxy or credential variables, and Pi's offline, version-check, and telemetry controls set. Pi's built-in extensions, retries, compaction, cache warming, and analytics are off.

The gate starts its own named Herdr server with that environment. Before creating any pane, it proves that the server it spawned, identified by process ID and start time, holds the listening socket that Herdr reports, and that every reported socket path lies inside the run directory. It then creates one anchor workspace and copies the `HERDR_*` values the anchor shell actually received. It checks that an implicit `herdr` call carrying those values resolves to the anchor, which is how the host's own Herdr calls reach the owned server. A single headless parent Pi then runs in RPC mode with that identity and with host, pstack, and the candidate active. Every Herdr command the gate issues names the owned session. A mutating command that times out marks the instance tainted, and it is never retried.

The loopback endpoint attributes each request while its connection is open. It finds the client socket in `/proc/net/tcp` and requires exactly one holder among the processes the run started and their descendants, including thread children. Every `/proc` read is classed as present, absent, or unknown. Absent means the process or file is gone. Unknown means the read was denied, malformed, or contradictory. A socket table counts as read only when every row carries the fields the gate uses and the table ends on a complete row. Unknown never counts as absent, and it refuses the request. The holder must run the selected Pi binary, with the same process ID and start time before and after its descriptors and environment are read. A host child must also descend from the owned server and carry the host's subagent identity, the owned Herdr session and socket, a pane other than the anchor, the owned agent directory, the offline flag, and no credential or proxy variable names. When a process's main thread has exited but other threads still run, it is read through a running thread. A recorded child that has lost its owned ancestry is attributed again only when every one of those values still matches its first proof. A request on a server connection that an earlier request proved is attributed to that earlier sender only when the sender is confirmed gone and its client socket is closed or held by no process. Each attribution records the checks it passed and its basis, and the result lists every request attributed without owned ancestry. Anything else is refused and fails the gate. Model labels and task markers are never used to identify a sender.

The scripted model has one response function for the parent and one per child scenario. Each function reads only the request it is answering. The parent never sees child requests or results except through the host's messages in its own context. A child's result is a nonce created only when that child's request arrives. Every wait is bounded and event-driven, and the gate never polls status or session files. A process counts as closed only when Node reports that it exited and that all of its output streams closed. An error event is not closure. On a deadline the gate signals through the process's own handle, never by a bare process ID. If closure still does not arrive within a further bounded wait, for example because a descendant keeps the output open, the process is reported unresolved, not closed. Packing and extracting the candidate follow the same rule. A packing command that stays unresolved is reported with its identity, and the run directory that holds it is kept until its close is observed.

The shared command helper bounds its post-signal wait to 1000 ms and captures at most 256 KiB per output stream. Its unresolved-command registry lives only in the test process. If that process exits first, the root stays on disk without a recovery service. Command closure proves direct-child and output-stream closure, not the exit of arbitrary descendants that detach from those streams. The helper neither identifies nor signals a descendant holding the output.

Teardown runs in an outer `finally` that also covers endpoint setup, the scenarios, and collection of the host's launch scripts. It attempts every step even when an earlier one fails, and keeps each failure:

1. Record the owned process tree.
2. Close each Pi process, escalating to signals only on deadline and recording any escalation.
3. Record the tree again, then stop the owned Herdr session once.
4. Close the endpoint.
5. Observe every recorded process identity as present, absent, or unknown, and look for owned sockets.

Evidence is written after teardown. The run directory is removed only when every recorded identity is confirmed absent, nothing is uncertain or unresolved, every step succeeded, and the evidence was written. Otherwise it is kept, and the test reports its path, every live identity, and every uncertain one.

| Distinction | Proves | Does not prove |
| --- | --- | --- |
| discovery | With all three packages active in one parent, the six `craft-*` skills come only from the candidate. Children are not queried over RPC. |
| standalone-role | A bare `systemPrompt` launched through the host's real `subagent` tool with `fork: false` reaches the child's first provider request inside the host's task artifact, with the complete role text before the complete task text. | That a model honors the role. |
| fork-control | With `fork: true`, the child inherits the parent conversation, and the turns after the inherited prefix are exactly the task without the supplied role. The inherited history keeps earlier launch arguments that contain role text, so a search of the whole request could not separate the cases. | Other inherited shapes. The measured inheritance ends before the launching prompt. |
| fresh-resources | A fresh host child issues real `read` calls for the candidate's craft-mode skill, its delegation reference, and its craft-tdd sibling. | completion | Each child result was minted only on that child's request. It reaches the parent as a real host `subagent_result` and then in a later parent provider request, and the controller never sent it. | Cancellation, stalls, or delivery of failed results. |
| handoff | Child A's value reaches the parent only through the host. The parent's own next response accepts it and launches child B through the host with it, and B's first request carries it. | Parallel or worktree-based handoff. |
| skills-argument | Requires the host's `skills: "craft-mode"` launch to keep the canonical instructions in the child's actual task request and to complete with a result derived from that task. | resource-controls | A package filter removes `craft-tdd` from registration, and its slash command reaches the model as raw text, yet the file stays readable through the read tool. An agent-directory skill and a decoy package of the same name win registration and are rejected by location. Unknown slash text reaches the model unchanged. A host whose extensions are disabled declares no `subagent` tool and is reported blocked. | That filters restrict file access, or the order of other shadow placements. |
| pstack-report | `/setup-pstack report` is handled as a command without a model turn or provider request, reads the owned task-model configuration, and leaves its bytes unchanged. | pstack's change or init flows. |
| pstack-mode | `/poteto-mode on`, `status`, and `off` are handled as commands with their documented transitions. While on, a `/skill:craft-tdd` prompt carries pstack's mode section, the canonical poteto-mode hub, and the complete craft-tdd instructions. | writer-refusal | A well-formed `subagents_write_task_models` call outside the setup flow is refused by pstack's writer gate. No dialog opens, and the owned configuration bytes are unchanged. | The approved setup write path. |
| isolation | Every provider request is attributed to an owned process by its recorded checks, not by its kind alone, and carries only the test key. Host children carry the owned Herdr session. No observation was lost to a full log, an oversized line, an output record cut off at the end of a stream, an incomplete or unparsable request, or an undelivered reply. No dialog, extension error, protocol fault, or diagnostic output occurs. A run that received no request is blocked. | The absence of other network traffic, or an OS sandbox. |
| teardown | Every recorded process identity is confirmed absent rather than unreadable, nothing is uncertain or unresolved, no owned socket remains, each direct process closed with exit 0 without escalation, every teardown step succeeded, and the endpoint closed. | Recovery after the test process itself dies. |

The gate passes only when every distinction passes and the run directory was removed after a clean close. One failing distinction fails the gate while the others still report their own results. Measured outcomes are in [compatibility](compatibility.md).

## Later gates

The default suite lists these as todo items:

- Host orchestration, fresh-child resources, and pstack coexistence. These are measured only by the separate integration gate above.
- Live-model adherence to the methodology. This is not measured and must not be read as passing.

The integration gate does not test cancellation, worktrees, parallel writers, or persistent children. Those remain owned by the host and unmeasured here.
